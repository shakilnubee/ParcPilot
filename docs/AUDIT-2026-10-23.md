## 🔴 PRIORITÉ HAUTE

### H1 — Chart.js chargé en version flottante sans intégrité (supply-chain)
`<script src="https://cdn.jsdelivr.net/npm/chart.js@4">` (flottant, **pas de SRI**) sur 6 pages :
`dashboard.html:672`, `pages/amendes.html:546`, `pages/entretiens.html:571`, `pages/factures.html:618`,
`pages/sinistres.html:444`, `pages/statistiques.html:342`. Un hijack du tag `@4` exécute du JS dans
l'origine `parc-pilot.fr` qui porte le jeton de session → exfiltration (le CEO voit toutes les sociétés).
**Fix** : épingler une version exacte + `integrity`/`crossorigin`, ou self-host.
**✅ CORRIGÉ — lot 1 (PR #1072, déployé le 2026-10-23)** : Chart.js **self-hébergé**
(`assets/js/vendor/chart.umd.min.js`, 4.4.6) sur les 6 pages, plus aucun CDN flottant.

### H2 — Deux XSS stockés (immatriculation non échappée)
`pages/entretiens.html:601` et `pages/factures.html:2049` : `${v}` (immat, donnée saisie/OCR) injecté brut
dans un `<option>`. Payload `"><img onerror=…>` → exécution chez un autre utilisateur / le CEO.
**Fix** : `FP.esc(v)`/`escapeHtml(v)` (+ `factures.html:2051` type, + `vehicules.html:3083/3088` marque).
**✅ CORRIGÉ — lot 1 (PR #1072)** : immat/type/marque échappés (`FP.esc`/`escapeHtml`) sur tous ces points
d'injection ; `postMessage` filtré par `origin` en plus (app.js + controle.html).

### H3 — Bug mois `toISOString` : graphe affiche le mauvais mois + rapport surcompte
`new Date(y, m-i, 1).toISOString().slice(0,7)` en France (UTC+1/2) décale d'un mois en arrière.
`dashboard.html:1045-1046` (barre « oct. » affiche les dépenses de **septembre**),
`statistiques.html:554`, `app.js:11011` + `13242` (« 12 mois glissants » = **13 mois**, rapport direction surcompte).
**Fix** : format local comme `ecran.html:141` (`y+'-'+String(m+1).padStart(2,'0')`).
**✅ CORRIGÉ — lot 2 (PR #1073)** : nouveau helper central `FP.ymLocal(d)` (mois en heure locale),
branché dans app.js + dashboard + statistiques → plus de décalage, « 12 mois » = 12 mois.

### H4 — Périmètre « flotte » incohérent : `estVendu` vs `horsFlotte`
Dashboard/Contrats/Budget excluent via `FP.horsFlotte` (vendu+cédé+restitué+archivé+HS) ; Véhicules & TCO Stats
via `FP.estVendu` (vendu seul). Un véhicule `restitué`/`hors service` est compté 52 ici / 51 là, et sa
TVS/assurance/leasing apparaît dans Stats mais pas dans Contrats/Budget.
`vehicules.html:2665`, `statistiques.html:364-366,735,758,780,781`, `budget.html:243`.
**Fix** : `FP.horsFlotte` partout pour « flotte active ».
**✅ CORRIGÉ (volet financier) — lot 2 (PR #1073)** : Stats (TCO/assurance/TVS) et Budget excluent
désormais via `FP.horsFlotte` (cédé/restitué/HS inclus) → plus de surcompte.
**⏳ RESTE 1 DÉCISION UTILISATEUR** : le **compteur** « flotte active » de `vehicules.html:2665` utilise
toujours `estVendu` — à trancher avec Shakil (un véhicule restitué/hors-service compte-t-il dans « actifs » ?).

### H5 — Régression perf : `data.js` (294 Ko) rechargé en bloquant à chaque navigation
Le gate cold-start (`<head>` de 25 pages, ex. `dashboard.html:631`) lit `fp_data_cache_v3_<soc>` mais le cache
est écrit en **v4** (`app.js:26`, `supabase-client.js:455/527`) → le test « cache complet » est toujours faux →
`document.write(<script data.js>)` **parser-blocking** à chaque page. **Fix** : aligner le gate sur `v4`.
**✅ CORRIGÉ — lot 2 (PR #1073)** : gate cold-start aligné sur `fp_data_cache_v4_<soc>` sur les 25 pages
→ le cache complet est reconnu, plus de rechargement bloquant de `data.js`.

## 🟠 PRIORITÉ MOYENNE

### M1 — Échecs silencieux (anti-perte, règle CLAUDE.md 0-perte ③)
- **EDL** : e-mail au conducteur avalé (`app.js:14483,14489` `catch{}` vide) → PDF jamais reçu, toast « ✓ enregistré ».
- **Import factures en LOT** : justificatif droppé sans alerte + compteur menteur (`factures.html:1471,1489`).
- **Note de frais** (unitaire & lot) : justificatif droppé en silence (`factures.html:2878,2839`).
**Fix** : retour visible (reproduire la logique `firstMailOk`/`fileUploadFailed` déjà présente ailleurs).
**✅ CORRIGÉ — lot 3 (PR #1074)** : EDL alerte si l'e-mail échoue (EDL quand même enregistré) ;
imports factures/notes de frais (unitaire + lot) **comptent et affichent** les justificatifs non joints.

### M2 — Tâches d'automatisation jamais purgées
`FP.automations._creerTache` crée des tâches (titre « <règle> — <immat> — CT dans N j ») que ni
`FP.tacheAutoObsolete` ni `autoTachesCT` ne reconnaissent (titre ≠ « contrôle technique »/« révision ») →
elles s'accumulent avec un label figé (`app.js:7021-7031`). De plus le trigger `ct` double `autoTachesCT`
(deux tâches CT par véhicule si une règle `ct` existe).

### M3 — Amende : date limite lue dans le mauvais magasin
`FP.relances.amendes` (`app.js:19125`) et `FP.recommandations` (`app.js:9690`) lisent `a.dateLimiteMinore/Forfaitaire`
qui ne sont **jamais** persistés sur l'amende (la source est `FP.getAmendeMontants(a.id)`). → l'amende ne remonte
jamais « à relancer avant majoration » et la reco tombe toujours sur l'estimation.
**✅ CORRIGÉ — lot 3 (PR #1074)** : `FP.relances.amendes`, `FP.recommandations` et `buildAlertes` lisent
la date limite via `FP.getAmendeMontants(a.id)` (la vraie source) → l'alerte « avant majoration » remonte.

### M4 — `documents` revenant à la suppression hors-ligne
`FP.persist.applyTo` (`app.js:12441`) ne réconcilie que vehicules/amendes/factures/conducteurs → un document
supprimé hors-ligne réapparaît depuis le serveur jusqu'au flush.

### M5 — Entretiens : agrégats groupés par plaque brute
`entretiens.html:950,1058` keyent par `i.vehiculeImmat` brut (pas `FP.normImmat`) → une plaque écrite
`HL724CD` et `HL-724-CD` compte double, splittant le coût d'entretien.
**✅ CORRIGÉ — lot 2 (PR #1073)** : agrégats groupés par `FP.normImmat(i.vehiculeImmat)`, libellé résolu
via `FP.vehByImmat` → une seule ligne par véhicule quel que soit le format de plaque.

### M6 — QR public expose toute la flotte
`vehicules_public` renvoie tous les véhicules sans connexion (choix assumé, mais à restreindre au véhicule
scanné + par société avant d'onboarder d'autres clients).

### M7 — Edge Functions : robustesse
`edl-sign` relais signataire suivant avalé si Resend échoue (`:334-344`) ; `km-collect` écrit tout le blob
`app_settings` pour l'historique inspections (concurrence, classe connue, `:817-831`) ; `km-relance` veille CT
sans dedup (double envoi si cron+test le même jour).

## 🟡 PRIORITÉ BASSE / HYGIÈNE
- **Pas d'en-têtes de sécurité HTTP** (HSTS/CSP/X-Frame-Options) — limite GitHub Pages ; atténuable par
  `<meta http-equiv=CSP>` + anti-framing, ou proxy CDN.
- **COLLECTION_KEYS** : ajouter `automationDone`, `ficheCols`, `ficheColsOrder` (maps keyées, fusion fine).
- **Amende `cle`** (télépaiement) absente de la signature `fp:data-ready` → édition pas rafraîchie entre appareils.
- **`filterSociete`** (`supabase-client.js:234`) comparaison sensible à la casse (masque au pire, n'expose pas).
- **postMessage** sans contrôle d'origine (`controle.html:697`, `app.js:19739`) — impact capé, défense en profondeur.
- **jspdf** : CDN `logos.html:91` sans SRI + drift version (vendored 2.5.1 vs CDN 2.5.2) ; `@playwright/test` dev advisory.
- **Perf ×10** : `sig()` reconstruit 2×/load (`supabase-client.js:497`), `findPrime`/`leasingContrat` O(V²)
  (`statistiques.html:724`, `budget.html:237`), « Voir tout » non virtualisé.
